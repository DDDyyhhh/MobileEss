# 路线预览导致odom过期：修复记录

日期：2026-10-20（America/Los_Angeles）。已部署到RK3588，`mower-console.service`保持enabled/active/running。此次只做观测和规划，没有创建行驶任务。

## 原因与修复

用户生成路线预览后，网页提示“odom数据过期；定位未就绪”，随后又显示定位已匹配。

同一现场复现时，规划期间网页请求最长阻塞0.865秒，出现5个odom或定位无效样本；空闲采样25秒未复现。独立订阅15秒收到451帧里程计，最大帧龄约13毫秒。进一步测量实际214位姿路线发现：原整车通行范围检查在RK3588每次耗时0.478–0.496秒，且在异步规划函数内同步执行。检查期间网页事件循环被占用，并与ROS/接收线程竞争Python执行时间，触发0.30秒新鲜度检查。

修复包括：

- 将目标点及候选路线检查移至后台执行，网页事件循环可继续处理状态和心跳。
- 将逐点、逐格的Python循环改为有界NumPy批量计算，维持完整实心包络检查。
- 保留原0.98m静态通行包络、≤0.05m路径采样、未知区/边界/障碍拒绝和原超时阈值。
- 增加事件循环响应回归测试，以及旋转地图、40m路线、包络内部障碍和未知区的对照测试。

没有通过放宽odom、TF或定位超时来消除提示。
