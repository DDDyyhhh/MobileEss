# A3停稳判定间歇失效：接收过滤修复

日期：2026-10-21（America/Los_Angeles）。A3搜索在35.519秒得到匹配，但后续稳定窗口因stationary=false退出，本次保留为未通过尝试。复现和修复全程为只读观测，未发车。

后续说明：本报告保留接收过滤阶段的结果。后来的45秒采样仍发现7次接收时序不一致，已另行完成[内核到达时间戳修复及A4复测](can-kernel-time-fix-20261021.md)；最新部署为该报告中的61文件版本。

## 复现与修改

原始A3失败前后，独立CAN接收显示四轮最大3mm/s、0x50A最大间隔69.791ms，API0。随后30秒被动对照采到320个HTTP状态，其中11次后端stationary=false；用同期独立CAN时间序列调用同一个RosAdapter.stationary方法，这11次均满足停稳。定位与数据健康状态始终有效。这将问题范围收敛到后端接收时序，未发现总线断流或超过10mm/s的轮速。

控制台原来先将整条CAN总线报文接收到Python，再丢弃无关报文。5秒并行探针显示：未过滤socket收到1698帧，内核过滤后收到204帧；两者0x507均122帧、0x50A均82帧，关键反馈计数一致，无关接收量减少约88%。

仅修改RosAdapter的接收socket：使用CAN_RAW_FILTER保留标准数据帧0x005、0x507和0x50A，掩码0xc00007ff同时限定标准ID与非RTR帧。0x005继续用于发现其他控制发送者。原停稳窗口、帧新鲜度、帧间隔、连续1秒及四轮≤10mm/s条件全部保留。

该单变量修改后，原先的后端/独立接收不一致在本轮对照中消失，结果支持无关报文接收负载影响后端时序的判断。原进程内部每帧接收延迟没有被直接记录，因此不将具体线程调度原因写为已测定事实。
