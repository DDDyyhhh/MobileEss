# Claude Code 速度与范围控制参考卡

## 模式速查

| 模式 | 目标 | 调查范围 | 验证 | 询问边界 |
|---|---|---|---|---|
| 极速开发 | 最快交付 | 直接相关文件 | 最小验证 | 仅真实阻塞或范围变化 |
| 正常开发 | 平衡速度与质量 | 相关实现、测试、调用方 | 相关测试/lint/typecheck | 实质歧义或高风险动作 |
| 生产变更 | 可回滚、可审计 | 影响链路与风险边界 | 完整相关检查 | 删除、迁移、发布、部署等 |

## 推荐任务开头

```text
模式：极速开发
目标：实现……
范围：只允许修改……
完成标准：……
验证：运行……
不要：无关重构、假设性错误处理、依赖升级、反复确认小决定。
```

## 何时提高模式

把 `极速开发` 提高到 `正常开发`：

- 改动跨多个模块；
- 需要修改现有测试或公共接口；
- 失败路径会影响用户体验或数据；
- 你不清楚项目已有约定。

把 `正常开发` 提高到 `生产变更`：

- 涉及生产环境、数据库、权限、支付或隐私；
- 涉及删除、迁移、推送、发布或部署；
- 失败后难以恢复；
- 需要改变 CI/CD、基础设施或外部服务行为。

## 速度的三个杠杆

1. **限制上下文**：先看入口、实现和相关测试，不要全仓库漫游。
2. **限制改动**：每个改动都必须能对应需求或验证。
3. **限制验证**：先跑最相关的最小检查，再按风险决定是否扩大。

## 权限分工

- `CLAUDE.md`：告诉模型如何工作。
- `.claude/settings.json`：允许或拒绝工具操作。
- hooks：执行确定性的自动检查或阻止规则。
