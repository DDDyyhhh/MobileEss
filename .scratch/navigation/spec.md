# 第一阶段：户外停车场四驱车建图、定位与自主导航

## 目标

在固定户外停车场内，让四驱差速测试车完成可重复的：

1. 人工采集并生成停车场地图；
2. 启动时自动初始化定位；
3. 接收预配置目标点或安全驻停点；
4. 通过 Nav2 自主规划和行驶；
5. 处理动态障碍物；
6. 到达目标或安全驻停位置后停车；
7. 通过 SSH、RViz2、ROS 2 话题和日志完成验证。

第一阶段以实际建图、定位和导航效果为优先，不为了理论完整性引入过度设计。

## 范围

### 包含

- Ubuntu 22.04 + ROS 2 Humble 的 RK3588 部署；
- Mid-360 3D LIO、点云建图、三维地图匹配和障碍物感知；
- RTK 全局坐标和固定 `earth → map` 标定；
- IMU 数据接入；
- MCU 通过 OID 实时电转速反馈；
- STM32 新增最小 `0x50A` 四轮实际线速度输出；
- RK3588 SocketCAN 接收和 `mcu_can_bridge`；
- `robot_localization` EKF 输出连续 `odom → base_link`；
- 二维 Nav2 地图和三维 Mid-360 定位地图；
- Nav2 全局规划、局部控制和动态障碍物避让；
- 固定停车场边界、禁行区、限速区和预配置目标；
- Standoff Point 的几何驻停判定；
- 普通障碍物停车、有限绕行和安全停车；
- SSH 启动、调试、日志和 RViz2 验证。

### 不包含

- 云端小程序、正式车身 GUI 和 MQTT 任务调度；
- 真实充电枪插接、线缆张力或充电握手；
- CAN `0x50B` 质量帧、序号、CRC、协议版本和其他协议加固；
- MCU 硬件看门狗或独立安全控制链路；
- 自研 SLAM、Nav2 规划器或控制器；
- 跨停车场、公共道路和恶劣天气运行；
- 强制 systemd、自启动和远程升级。

## 已确定的底盘与 CAN 接口

底盘确定参数：

- 四驱差速；
- 实心轮径 `0.24 m`；
- 物理轮距 `0.690 m`（左右轮胎接触面中心线距离）；
- 减速比 `4.43`；
- OID 极对数 `10`。

控制接口：

- RK3588 只通过 STM32 的 `0x005` 主控帧控制底盘，不直接控制 OID 节点；
- CAN 使用经典 CAN、标准帧、`500 kbit/s`；
- 控制帧约 `50 ms` 周期发送；
- 按 `ctrl_mode=1 → 2` 两步进入 API 运行；
- `0x507` 保持现有指令回显语义；
- `0x50A` 由 MCU 完成 OID 电转速到四轮实际线速度的换算后发送：

```text
Byte 0~1：前左，int16，0.001 m/s
Byte 2~3：前右，int16，0.001 m/s
Byte 4~5：后左，int16，0.001 m/s
Byte 6~7：后右，int16，0.001 m/s
```

MCU 继续使用现有约 `500 ms` 上位机控制帧超时停车和锁存。该机制属于应用层超时，不称为硬件看门狗。

## 定位与 TF

```text
earth → map → odom → base_link
```

- `earth → map`：建图时测量并固定保存；启动时加载并校验；
- `map → odom`：Mid-360 激光地图匹配持续校正，RTK 做全局一致性辅助；
- `odom → base_link`：`robot_localization` EKF 融合 LIO、IMU 和轮速 twist；
- RTK 单帧异常不能直接造成车辆位姿跳变；
- RTK 失锁但激光地图匹配正常时继续运行；
- RTK 与激光匹配同时退化时进入受限死算模式，并根据实际质量减速或停车。

车辆位于固定起始区时，启动流程为：加载地图和标定 → RTK 粗定位 → Mid-360 地图匹配精定位 → 通过质量条件后允许导航。

## 导航行为

- `global_costmap` 使用二维静态地图、边界、禁行区和限速区；
- `local_costmap` 使用 Mid-360 点云处理临时障碍物；
- 障碍物进入减速区时降速，进入停止区时停车；
- 默认停车等待，障碍物持续存在时才有限重规划；
- 无安全路径时保持停车并上报；
- 不驶出作业边界，不进入禁行区；
- 普通障碍物停车在条件恢复后自动恢复；
- 碰撞、软件急停、遥控器接管和 CAN 超时锁存需人工复位。

任务节点负责目标校验、Standoff Point 选择和最终结果；Nav2 `NavigateToPose` 只负责几何导航。第一阶段的 Standoff 结果只说明按几何模型可安全驻停，不等同于充电成功。

## 建图流程

1. 人工遥控采集停车场主要道路、边界和目标区域；
2. 记录 Mid-360、LIO、IMU、RTK 和轮速数据；
3. 离线生成并检查二维规划地图和三维定位地图；
4. 清理或剔除临时车辆、行人等动态物体；
5. 固化地图版本、坐标系、建图日期、传感器外参和 `earth → map` 标定；
6. 用独立路线验证定位和地图匹配效果。

## 验收基线

### 定位

- 正常运行水平定位误差：95 分位不超过 `0.30 m`；
- RTK 固定解时目标水平误差：不超过 `0.10 m`；
- 目标到达位置误差：不超过 `0.30 m`；
- 目标航向误差：不超过 `10°`；
- 最终车速低于 `0.05 m/s` 才判定停车到点。

### 轮速反馈

- MCU 能查询 OID 四个行走电机的实时电转速；
- MCU 能按确定参数输出 `0x50A` 四轮实际线速度；
- RK3588 能解析 `0x50A`，计算左右侧平均速度；
- `mcu_can_bridge` 发布标准 `geometry_msgs/msg/TwistWithCovarianceStamped`，只使用 `twist.linear.x` 和 `twist.angular.z`；
- `pose` 不作为轮速定位输入；
- `0x50A` 连续超过约 `150 ms` 未收到时暂时停用轮速观测，不用零值或上一帧伪造；
- 轮速恢复后连续收到正常帧再恢复融合。

### 导航

- 能从固定起始区自动完成初始化定位；
- 能从起始区导航到至少一个预配置停车场目标；
- 能在临时障碍物出现时减速或停车；
- 障碍物持续存在时能有限重规划或安全停车；
- 不驶出停车场边界；
- 能到达目标点或经过几何覆盖验证的 Standoff Point。

### 控制与运维

- RK3588 通过 SSH 启动统一 ROS 2 launch；
- 定位未确认前不发送非零速度；
- 通过现有 `0x005` 完成 MCU API 接管；
- MCU 碰撞、软件急停和倾翻保护保持有效；
- RK3588 正常发送零速度时车辆可停车；
- CAN 控制帧中断超过约 `500 ms` 时，现有 MCU 应用层超时逻辑可停车并锁存；
- 可通过 SSH、RViz2、`ros2 topic` 和日志检查定位、TF、轮速和 Nav2 状态。

## 任务拆分与执行规则

本规格由可现场执行的任务票落实，任务总览见 [map.md](map.md)，具体任务见 [issues/](issues/)。

每张任务票只对应一个独立的现场或离线动作、一个可判定输出和一个安全退出点。票据必须写明设备/固件/地图版本、手动命令或操作、观测点、预期效果、失败安全退出、证据和通过阈值。

任务文档阶段只创建执行说明，不刷写固件、不修改实车配置、不执行上车操作。实际执行时按 `map.md` 的 `Blocked by` 顺序推进；只有实测效果通过并归档证据后，任务才可标记为 `resolved`。优先验证建图、定位和导航实际效果，不因理论完整性增加协议加固或复杂防御逻辑。

统一证据至少包括：执行日期、车辆/固件/软件版本、地图/参数版本、命令或人工步骤、关键 ROS 话题/TF/CAN 观察、日志或 rosbag、RViz2 截图或现场视频、实测结论。

1. 确认 RK3588 系统、ROS 2 Humble、SocketCAN 和 Mid-360/RTK 驱动环境；
2. 以现有 `0x005` 打通 STM32 API 接管和四驱速度控制；
3. 在 MCU 中以最小改动实现 OID 实时电转速读取和 `0x50A`；
4. 在 RK3588 实现 `mcu_can_bridge`，发布轮速 twist；
5. 接入 IMU、Mid-360 LIO 和 `robot_localization`；
6. 完成停车场人工建图和双地图固化；
7. 完成自动初始化定位和 TF 验证；
8. 配置 Nav2 全局/局部代价地图和差速控制器；
9. 先无障碍实车导航，再验证动态障碍物、停车和恢复；
10. 根据实际失败现象调整参数，不提前扩展协议或架构。
